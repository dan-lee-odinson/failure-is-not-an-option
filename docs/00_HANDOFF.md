## 3. What the player does in 0.4.0 — so you know what you are building

Preparation: choose up to two of three ground rehearsals (contact, recovery, systems). Docking. A communications gap. The crisis report arrives through the tracking ship; the crew stabilize the spacecraft; the RCS rule ends the mission. Then **the decision**: bring the crew down at the earlier modeled opportunity (off the damaged spacecraft sooner; a long sea wait) or take one additional modeled orbit (concentrated recovery coverage; control reserve critical). Both always available. A deterministic execution event grades how well the room executes the chosen order from which rehearsals were performed (six resolutions, six outcome records with distinct titles). Two fictional controllers, Mara Voss and Elias Reed, react with trust deltas. A baseline procedure is adopted. Then a **post-flight scene**: a sourced historical disagreement (H5) is shown, and Glen either sides with the critics and blames the crew (Armstrong and Scott −2, Cunningham and Stafford +1, corps division fact) or takes Kranz's reported ground-contingency position (Armstrong and Scott +1, commissioned task added to the procedures binder). Finalization commits exactly one of six outcomes. The **Gemini IX-A follow-on** is now a small playable planning screen initialized from the committed ledger only: three two-drill plans, one disabled per route with its reason shown, one committed by a recorded input.

An ALTERNATE HISTORY badge appears from return planning onward. Every simulated report is labeled. The historical context card in the post-flight scene shows the criticism and the exoneration together and is never altered by the player's stance.

## 4. Fixed decisions — do not reopen

- **Engine:** TypeScript + HTML/CSS. Vite, Vitest, Playwright, Ajv. No WebGL library, no desktop wrapper, no framework beyond what Vite scaffolds. Local browser build; hosting is a later step.
- **2D, layered illustration, first-person framing from the director's console.** All readable text is application-rendered; nothing meaningful is baked into art. The brief status panel in the return beats is application UI over the same room asset.
- **All dialogue on screen. No voiced or intelligible spoken lines.** Ambient audio optional; if present it carries no information.
- **No timers, no pressure mode, no chance draws, no patches or wardrobe** in M00. The seed is stored and logged; this content makes zero draws. `people.<id>.trust` adjustments ARE in scope (integers, no clamping, recorded before/after with cause).
- **Simulation core is engine-free:** no DOM, no timers, no rendering in `core/`. Content is data, never code.
- **Saving:** one browser-storage slot plus JSON export/import. Import validates structure, versions, references, and replay equivalence before replacing anything; a failed import leaves the existing save untouched and tells the player. Save boundaries are the ones the specification lists under "State invariants".
- **Open source, noncommercial.** Initialize git locally. **Do not create a remote or push.** Add `LICENSE` (MIT) for code and `LICENSE-CONTENT` (CC BY 4.0) for `content/` and `assets/` as *proposed* files with a header line saying Dan confirms before publication.
