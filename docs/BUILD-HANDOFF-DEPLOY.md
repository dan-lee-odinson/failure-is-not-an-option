## Part 2 — the film in the opening

**The deployed cut.** `public/video/opening-film.mp4` — manifest `video-opening-film`, a new `video` kind in `schema/manifest.schema.json` (`duration_s`, `sha256`, credit and rights lines), validated on disk by the validator (present, MP4 signature). It is the assembly master of film v002 (docs/deploy-inputs/38 §2) trimmed to 0:00 → 2:18.000 exactly (4140 frames; the last frame is the wide den at rest), 1920×1080/30, H.264 High 4.1, AAC 144 kb/s, faststart. **Size: 27.0 MB, not the 20–25 MB target:** at the handoff's CRF 23 the trim came out at 52.7 MB (grainy 1080p archive footage), so it is a two-pass encode at 1400 kb/s instead — the smallest rate that keeps the footage from breaking up — which lands under the release check's 30 MB line. If Dan wants the 20–25 MB target regardless, 1100 kb/s does it at a visible cost on the launch shots (one line in `provenance/assemble.py`'s trim stage). One file: H.264 plays in Playwright's bundled Chromium ("probably" for `avc1.640028`), in Chrome, Edge, Firefox on Windows/macOS and Safari, so no WebM was added.

**Playback** (`app/main.ts`, `playFilm`). The `film` stage renders one native `<video>` (`playsinline preload="auto"`, no controls, not muted) letterboxed in the viewport; `play()` is called inside the Begin click. The element survives repaints: the film stage repaints its controls only (`renderFilmControls`), so the sound toggle, the volume slider and the idle highlight never rebuild the video. Its volume is master × music and SOUND: OFF mutes it; the director plays nothing during the film (no cue triggers on `screen:opening-film`). Hand-over at **2:18.0** (`FILM_HANDOVER_S`): `timeupdate`, `requestVideoFrameCallback` where available, and `ended` all lead to `enterCredits(false)`; the video is stopped, unloaded and removed. Failure fallback: `error`, a rejected `play()`, or no playback within 8 s → the den with the credits, never a blocked menu (all three apply only while that element is still the film: a `play()` rejected because Skip stopped it is not a failure).

**The live den from 2:18** (`renderCredits`, `driveDen`). The den plate in the `.pl-frame` design frame; the beam at `registry.opening_den.beam.placement` at 0.32 with a Web Animation flicker (24 steps over 2.4 s, ±8 %, a seeded pattern — mulberry32, seed 19660316 — so every run and every test sees the same pattern); two smoke instances at the smoke placement, each rising −55 design px over 12 s with the 3 s crossfade weights, the second started 9 s later (period 18 s), reset while invisible. Animations are re-created after every repaint at the time they had reached (like the prologue's layer), so Pause or a sound toggle never resets the smoke. Reduced motion: one static smoke instance, a static beam, no animations.

**The credits on the wall.** Inside `projection_rect` (830, 115, 928×522 design px): the dedication, the three notices, then `registry.credits` in order, dark ink (`--paper-ink`, #152824) on the plate's own lit rectangle, Barlow for the lines and Barlow Condensed for the headings, 22 design px body (26 at enlarged text). The scroll is the M00c mechanism (`#op-scroll`, rAF-driven, `scrollTop` kept across repaints) at **72.5 design px/s** — the handoff says "≈150 design px/s", but 150 px/s is the film's rate at its 1920-px slot resolution; the rectangle is 928 design px wide, so the same pace is 72.5 design px/s, which is also what "each line on the wall about seven seconds" means (522 / 72.5 = 7.2 s). It starts one second after the den appears (the film's own blank second). Pause / Resume, manual scrolling while paused, Continue (quick fade to the title), Skip to menu — all outside the wall. *Orbit of Hope (refrain)* plays under it: music-map cue `credits` (trigger `screen:opening-credits`, from 0:00, fade 2 s on the `opening-runout` signal, 0.4 s under Continue). The M00c `opening` cue is retired with the prose scroll.

**Run-out** (`startRunout`, `RUNOUT`): last line cleared → 1.2 s hold → the beam dies with two stutters (0.6 s, a Web Animation) → the den darkens over 1.5 s (`.den-dark`) → 0.5 s black (controls hidden) → the title dissolves in over 700 ms (`fade-in den`); the wall's focus ring is suppressed from the moment the run-out begins. Skip during the film → the den with the credits as a static, keyboard-scrollable block (`creditsStatic`), Continue → title. Reduced motion → no video at all: Begin goes straight to the wide den with the static credits; cuts.

**Sound.** The M00c rule holds: Begin turns the master on unless the player has set it; that same click permits the film's audio. **The sheet** gains SKIP FILM and the credits' `Credits` label; PAUSE / RESUME / CONTINUE / SKIP TO MENU as before; the credits sections are `credits.heading` / `credits.line` with `registry.credits.<n>` ids on the `opening-credits` stage (they were an "awaiting assembly" bucket in 0.5.4's sheet).

## Part 4 — the workflows

`.github/workflows/pages.yml`: push to `main` or manual dispatch → checkout → Node 24 → `npm ci` → `npm run validate` → `npm test` → `npm run build` → `npm run release-check` → `configure-pages` → `upload-pages-artifact` (`dist/`) → `deploy-pages`; permissions `pages: write`, `id-token: write`; concurrency group `pages`. A failing step publishes nothing. `.github/workflows/ci.yml`: pull requests and non-main pushes run the same checks plus `typecheck`, the Playwright install and `npm run test:e2e`, uploading screenshots and results as an artifact. The browser suite is kept off the deploy path deliberately: it needs a browser install and minutes of wall time, and the deploy path should be short and deterministic; a pull request is where the suite reviews a change.

## Decisions taken here (reversible)

1. **27 MB, not 20–25 MB** (above): two-pass 1400 kb/s; CRF 23 would have been 53 MB.
2. **72.5 design px/s** for the wall credits, the film's own pace expressed in the rectangle's pixels (the handoff's "≈150 design px/s" would run twice as fast as the film and put each line on the wall for 3.6 s).
3. **The credits stage keeps the M00c scroll mechanism** (a real scroll box: Pause, manual scrolling, keyboard) rather than a transform animation, so the static and the timed variants are one block.
4. **One video file.** No WebM: H.264 played in every browser the suite and the handoff name.
5. **The home page is rendered by a Vite plugin from the registry** rather than committed as HTML; the stub `index.html` says so. A content change to `registry.site` is a rebuild, no code.
6. **Fonts once.** The site uses `public/fonts/` (with the OFL files) instead of v001's second copy under `site-assets/fonts/`; the OFL notices in v001's copy were identical.
7. **The sheet's credits rows are content** (`credits.*`, `registry.credits.<n>`), not app copy; 0.5.4's "awaiting assembly" bucket is gone because the strings are now reachable.
8. **`ci.yml` runs on pull requests and non-main pushes**, not on `main`: the deploy workflow already runs the non-browser checks on `main`, and running both there would double the cost of every push without adding a gate.
