## 2. Claude's triage

**Note 1 — sound on by default. Diagnosed: case (a), a display/default-state problem, not a regression.** On a fresh profile the opening start screen renders the toggle as SOUND: OFF before the first gesture, and one click flips it to ON — so the stored state is "unset", the toggle paints "unset" as OFF, and a first click sets it on. Begin would have armed sound anyway (the M00c rule), but the player reads OFF as "this game is silent by default" and either clicks the toggle (harmless) or assumes there is no sound. Fix for Claude Code (batch with the rest of doc 49): the unset state renders as **SOUND: ON** everywhere the toggle appears (opening start, film, credits, menu, room, prologue, resolution); the first user gesture on any key — Begin, Skip, the menu play keys, the toggle itself — arms the audio context; clicking the toggle from the unset/ON state turns sound **OFF** and persists "off"; a persisted "off" is the only thing that renders OFF; the volume slider is unchanged. Update the m00c/m02 sound cases and the phone walk to assert the pre-gesture label. No content change.

**Note 2 — full-screen reminder before the film.** Claude Code, app copy. The opening start screen (BEGIN / SKIP TO MENU) gets the same line the menu already carries ("Best played full screen — press F11 on Windows"; Dan's alternative wording: "This game displays best on full screen, press F11 on most keyboards to switch to Full Screen mode") and a FULL SCREEN key beside SOUND, using the same Fullscreen API call as the menu key. One sheet row; no content change.

**Note 3 — flash at the film → credits hand-over, "frames visible briefly".** Claude Code, presentation bug. At 2:18.0 the video element is stopped and removed and the den layers are rendered; for at least one frame something else is painted — the letterbox/design-frame edges or the unstyled den before its layers compose. Fix: render the den (plate, beam, smoke) *underneath* the video before the hand-over, then swap by opacity in a single frame (`requestVideoFrameCallback` → set video opacity 0 and remove on the next frame), so nothing but the last film frame and the first den frame are ever visible. Test: capture the frame before, at and after the hand-over and assert no frame differs from both neighbours by more than a threshold (no black/white flash, no frame edges).

**Note 4 — leaving full screen during the credits hides the credits; re-entering restores them.** Claude Code, bug. A resize during the credits triggers the repaint path; the credits sheet is lost or positioned outside the projection rectangle at the new scale until the next repaint at the old size. The deploy build said `scrollTop` is kept across repaints; the visibility isn't. Fix: on resize during the credits, recompute the rectangle and re-attach the same scroll box in place, preserving `scrollTop` and the running state (Pause/Resume). Test: resize 1920→1200→1920 mid-credits, credits visible and at the same line throughout; also covers F11 in and out.

**Note 5 — short lag on the prologue plates.** Claude Code, presentation. The plates are large images loaded on demand. Fix: preload the five prologue plates, the scenario card plate and the first room plate during the credits (or on Begin), reveal each plate only after `img.decode()` resolves, and fade from black rather than pop; keep the same rule for the resolution-card plates before the resolution screen. Test: with a throttled network profile, no plate shows partially loaded; the first plate's fade starts only when decoded.

**Notes 6 and 7 — the Binder's reference pages and the Evidence items are visible before the play has earned them.** This is the biggest item and it is half content, half engine. Today the four reference pages sit in the Binder from the first minute, and the "Mission termination after RCS activation" page alone tells the player how the mission goes. Evidence has the same problem in two forms: items available before the scene that would present them, and items that unlock silently so the player never sees them arrive. **Proposed standing rule (R2, Dan to confirm): nothing appears in the Binder, the Evidence overlay or the History panel before the player has met it in play, and when something is added the player sees it happen.** Split: **Codex (content 0.5.5)** — every reference page and every evidence item gets an explicit `unlocked_by` (a node id, a line id, or a preparation choice) audited against the script so the unlock is the scene that presents the information; the two drills unlock with the preparation choice that adopts them; "Network coverage and report timing" unlocks at the loss-of-contact scene; "Mission termination after RCS activation" unlocks when Mara reports the RCS activation, not before; items the script never presents are cut or given a presenting line. **Claude Code (engine + presentation)** — the Binder and Evidence read `unlocked_by` and hide anything not yet reached (availability is derived from state, so nothing enters the replay log); a short, quiet cue when something unlocks — the EVIDENCE · n counter ticks with a one-second highlight and a one-line strip "Added to evidence: <title>" (same for "Added to the binder"), dismissed on the next click; the Binder's empty state reads "Nothing adopted yet. Reference pages appear as the mission gives you them." Validator: an evidence item or reference page without `unlocked_by` fails validation.

**Note 8 — an asked question stays drawn as a live key.** Claude Code, presentation, same treatment as the decision cards: once a question is asked its key greys and carries a small ASKED stamp (the CHOSEN/ORDERED stamp family), keyboard focus skips it, and when every question in a scene has been asked the row collapses to the reply. No content change.
